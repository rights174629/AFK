# 🪵 Keep the Fire Alive (불꽃 지키기 / 멍불)
> **"누군가 장작을 넣지 않으면, 이 불은 꺼집니다."**  
> 전 세계 접속자가 단 하나의 실시간 가상 장작불을 함께 돌보며 대화를 나누는 힐링 웹 서비스 개발 계획서 및 기술 예외 대응 전략

---

## 1. 프로젝트 개요 및 기술 환경 선정 (Overview & Architecture Decision)

### 1.1 기획 의도 및 서비스 철학
- **단 하나의 공유된 불꽃 (Single Global Session)**: 수많은 접속자가 개별 방이 아닌, 단 하나의 전역 세션에서 동일한 불꽃을 실시간으로 함께 바라봅니다.
- **장작불 곁의 고요한 대화 (Campfire Community)**: 타닥거리는 장작 소리와 불티 속에서 접속자들이 따뜻한 온기와 일상의 소회를 나눌 수 있는 **미니멀 픽셀 채팅 시스템**을 제공합니다.
- **체류의 기록 (Stay Duration)**: 접속자가 언제 들어와 얼마나 오랫동안 불을 쬐며 쉬어갔는지 개인 세션 체류 시간을 기록하고 시각화합니다.
- **고요한 ASMR & 멍때리기**: 공부, 독서, 수면 전, 업무 중 서브 모니터나 백그라운드 탭에 띄워두는 앰비언스 힐링 공간입니다.

### 1.2 기술 스택 선정: 왜 `Node.js + Socket.io` 동적 웹 환경인가?

실시간 채팅, 1초 단위 전역 불꽃 계산, 장시간 상시 가동, 다방면의 최적화와 관리 편의성을 비교 분석한 결과 **`Node.js + Express + Socket.io`**가 가장 최적의 아키텍처로 선정되었습니다.

| 평가 기준 | **Node.js + Socket.io (최종 선정 ⭐️)** | Python Flask (Flask-SocketIO) | 순수 정적 웹 + Firebase |
| :--- | :--- | :--- | :--- |
| **언어 일원화** | 프론트(`JS`)와 백엔드 모두 **JavaScript 하나로 일원화**되어 컨텍스트 스위칭 없음 | Python과 JS 두 언어를 관리해야 함 | JS 단일 언어 |
| **실시간 동시성 & I/O** | **싱글스레드 비동기 이벤트 루프(Event-Loop)**로 수천 명 동시 접속 시에도 CPU/메모리 소비 극소화 | GIL 및 WSGI/ASGI(gevent/eventlet) 멀티프로세스 튜닝 필요 | 실시간 DB 읽기/쓰기 쿼리 비용 발생 |
| **네트워크 자동 복구** | WebSocket 단절 시 자동 폴링 폴백(HTTP Long-polling) 및 **지수 백오프 자동 재연결 내장** | 재연결 및 엔진 호환성 수동 처리 빈도 높음 | SDK 내장 |
| **중앙 1초 틱 연산** | `setInterval` 논블로킹 타이머로 서버 메모리에서 불꽃 틱 연산 및 초고속 브로드캐스트 | 백그라운드 스레드 분리 및 잠금(Lock) 관리 필요 | 서버리스 환경에서 1초 주기 틱 구현이 매우 난해함 |
| **인프라 비용 & 배포** | 별도 서버 컴퓨터 불필요. Render, Fly.io, Railway 등 **무료 클라우드 티어 완벽 호환** | 파이썬 웹소켓 지원 무료 호스팅 제약 | 무료 사용량 초과 시 과금 위험 |

### 1.3 인프라 및 서버 구동 계획
- **개발 환경 (Local Development)**: 
  - 별도 서버 하드웨어가 전혀 필요 없으며, 현재 작업 중인 개인 PC에서 `node server.js` 명령어로 서버를 가동.
  - 브라우저 창을 2~3개 띄워 `https://localhost:3000`으로 접속하여 **동시 접속자 카운팅, 실시간 불꽃 상태, 장작 투입, 실시간 채팅**을 즉각 검증.
- **배포 환경 (Production Deployment)**:
  - 24시간 상시 가동을 위해 내 컴퓨터를 켜둘 필요 없이 **Render / Fly.io / Railway** 무료 티어에 Git 레포지토리 연결로 자동 배포.
  - 무중단 환경 유지를 위한 로컬 파일 기반 스냅샷 영속화.

### 3.1 UI/UX 세부 사양
1. **캔버스 레이아웃 (Canvas)**:
   - 해상도 320x180의 내부 버퍼를 생성하고 CSS `image-rendering: pixelated;`로 화면 크기에 맞춰 정수배 업스케일링하여 레트로 픽셀 질감 극대화 및 GPU 부하 최소화.
   - 불길의 강도(`fireLife`)에 따라 화로 주변 지면을 비추는 **동적 방사형 앰비언트 라이트(Radial Light Pulse)** 연출.
2. **정보 인디케이터 (Top Bar)**:
   - **좌측 상단**: 개인 체류 시간 (`⏳ 내가 머문 시간: HH:MM:SS`) - 로컬 `Date.now()` 차분 기반 실시간 누적 카운트.
   - **상단 중앙**: 불꽃 전체 생존 시간 (`DAY xx · xx:xx:xx`).
   - **우측 상단**: 실시간 동시 접속자 수 (`● N명이 함께 불을 쬐는 중`), 채팅창 토글, 사운드 볼륨 제어.
3. **실시간 장작불 미니멀 채팅 피드 (Campfire Chat)**:
   - 배경의 불꽃을 가리지 않도록 **반투명 픽셀 글래스모피즘(Backdrop-filter blur 8px)** 적용.
   - 메시지 자동 페이드: 20초간 새 메시지가 없으면 텍스트가 은은하게 반투명화.
   - **자동 배정 익명 닉네임**: 첫 접속 시 따뜻한 수식어 + 동물 조합 자동 부여 (`포근한 사슴`, `조용한 고양이` 등).
4. **인터랙션 버튼 (하단 중앙)**:
   - 픽셀 도트 형태의 장작 아이콘. 클릭 시 둔탁한 타격음과 함께 장작이 포물선을 그리며 불길로 투입.
   - 3분 쿨다운 프로그레스 게이지 표시.

### 3.2 사운드 엔진 (Web Audio API 하이브리드)
- **메인 타닥거림 (Crackle)**: 밴드패스 필터를 통과한 화이트 노이즈와 비정주형 앰프 스파이크를 결합하여 외부 음원 없이 실시간 합성.
- **불길 베이스 (Rumble)**: 핑크 노이즈 + 로우패스 필터(80~200Hz)로 아늑하고 묵직한 불길 진동음 생성.
- **밤바람 앰비언스 (Night Wind)**: 불이 약해질수록 타닥거림은 줄어들고 스산한 바람 소리가 전면으로 페이드인.

## 4. 백엔드 시스템 및 Socket.io 통신 프로토콜 설계

### 4.1 상태 머신 (State Machine) 및 밸런스 공식
- **불꽃 체력 범위**: `0.0` ~ `100.0`
- **상태 구간**:
  - `BLAZING (70~100)`: 거대한 불꽃, 많은 불티, 가장 큰 사운드, 넓은 광원.
  - `STEADY (30~69)`: 아늑하고 안정적인 기본 장작불.
  - `DYING (1~29)`: 붉은 숯과 연기, 낮은 불길, 바람 소리 강조.
  - `EXTINGUISHED (0)`: 불꽃 꺼짐, 차가운 재, 흑백 화면 필터 적용.
- **자연 감쇠 공식**: 1초마다 `0.1` 감소 (100에서 0까지 약 16분 40초).
- **장작 1개 회복량**: `+8.0` (최대 100.0).
- **1인당 쿨다운**: 3분 (180초). 혼자서는 불을 유지할 수 없으며 최소 2~3명의 주기적 협동이 필요.

### 4.2 Socket.io 이벤트 명세서

| 이벤트명 (Event) | 방향 | 페이로드 (Payload) | 설명 |
| :--- | :---: | :--- | :--- |
| `connection` | C -> S | - | 클라이언트 최초 접속 (초기 종합 상태 전송) |
| `fire_init` | S -> C | `{ life, status, startTime, stayTimeBase, users, recentChats }` | 접속자에게 현재 불꽃, 생존 시간, 접속자 수, 최근 채팅 30개 일괄 전송 |
| `fire_tick` | S -> C | `{ life, status, serverTime, users }` | 서버가 1초마다 모든 클라이언트에 브로드캐스트 |
| `add_log` | C -> S | `{ clientToken }` | 유저가 장작 투입 클릭 시 요청 |
| `log_added` | S -> C | `{ newLife, senderNickname }` | 장작 투입 성공 브로드캐스트 (불티 이펙트 트리거) |
| `cooldown_error`| S -> C | `{ remainingSeconds }` | 쿨다운 중 중복 투입 시도 시 거절 알림 |
| `send_chat` | C -> S | `{ message, nickname }` | 유저가 채팅 메시지 전송 시 |
| `new_chat` | S -> C | `{ id, message, nickname, timestamp }` | 검증 완료된 새 채팅 메시지 전송 |
| `fire_extinct` | S -> C | `{ durationString, totalLogs }` | 불꽃 소멸 시 최종 기록 및 부활 모달 활성화 |
| `strike_flint` | C -> S | - | 부활을 위한 부싯돌 타격 신호 (3명 협동) |
| `disconnect` | C -> S | - | 접속 종료 (접속자 수 즉시 -1 반영) |

## 5. ★ 잠재적 변수 및 오류 전수 분석 & 대응 전략 (Error & Risk Management)

Node.js + Socket.io 환경에서 실시간 힐링 웹을 안정적으로 운영하기 위해 **13대 핵심 오류 및 변수에 대한 구체적 방어책**을 수립합니다.

---

### [오류 1] 브라우저 자동 재생(Autoplay Policy) 차단 및 사운드 먹통
- **원인**: Chrome, Safari 등 모든 모던 브라우저는 사용자 제스처(클릭, 터치 등)가 없는 상태에서 `AudioContext`의 시작을 강제로 `suspended` 상태로 블록.
- **대응 전략**:
  1. 페이지 진입 시 화면 정중앙 하단에 아늑한 픽셀 안내창 배치: *"불꽃의 온기를 들으려면 화면을 한 번 클릭하세요."*
  2. 첫 인터랙션(화면 어디든 클릭/탭) 즉시 `audioContext.resume()` 호출 후 안내창 페이드아웃.
  3. 로컬 스토리지에 유저의 음소거/볼륨 선호 상태를 영구 저장하여 재방문 시 유저 설정 존중.
  4. 외부 오디오 파일 다운로드 실패 시 Web Audio 노이즈 생성기를 **폴백(Fallback)**으로 가동하여 무음 상태 방지.

---

### [오류 2] 백그라운드 탭 스로틀링으로 인한 개인 체류 시간 및 불꽃 왜곡
- **원인**: 브라우저 백그라운드 탭 전환 시 `requestAnimationFrame`은 멈추고 `setInterval`은 1분에 1회 수준으로 극단적으로 지연(Throttling)됨. 단순 `count++` 방식 타이머는 시간이 멈추거나 느려짐.
- **대응 전략**:
  1. **절대 시각 차분 방식 (Date.now Difference)**:
     ```javascript
     // ❌ 잘못된 방식: setInterval(() => staySeconds++, 1000)
     // ⭕ 올바른 방식:
     const elapsedMs = Date.now() - sessionStartTime;
     renderStayTime(elapsedMs);
     ```
  2. **Page Visibility API 연동**:
     ```javascript
     document.addEventListener("visibilitychange", () => {
       if (document.visibilityState === "visible") {
         // 탭 복귀 즉시 서버에 최신 상태 재동기화 요청
         socket.emit("request_sync");
       }
     });
     ```
  3. **선형 보간(LERP)**: 탭 복귀 시 급격한 수치 튐 현상을 부드럽게 보간 렌더링 (`currentLife += (targetLife - currentLife) * 0.1`).

---

### [오류 3] 네트워크 단절 및 WebSocket 재연결 시 상태 고착 (Disconnection)
- **원인**: 모바일 절전 모드, 와이파이 전환, 일시적 ISP 장애로 소켓 세션이 끊길 때 유저가 고립됨.
- **대응 전략**:
  1. **Socket.io 내장 지수 백오프(Exponential Backoff)**: 1초, 2초, 4초, 8초 간격으로 백그라운드 자동 재연결.
  2. **비침해적 UI 상태 표시**: 우측 상단 접속자 수를 `● 연결 재시도 중...`으로 은은하게 깜빡이게 표시하되 불꽃 캔버스와 사운드는 로컬 캐시로 계속 부드럽게 유지.
  3. **재연결 핸들러 (`socket.on('connect')`)**: 재접속 완료 즉시 `fire_init` 패킷을 받아 불꽃 상태와 놓친 최근 메시지를 일괄 복원.

---

### [오류 4] 장작 투입 동시성(Concurrency) 충돌 및 경합 상태 (Race Condition)
- **원인**: 불이 꺼지기 직전 수십 명의 유저가 동시에 장작을 넣을 때 발생하는 연산 덮어쓰기.
- **대응 전략**:
  1. **Node.js 싱글스레드 특성 활용**: Node.js는 이벤트 루프 기반으로 각 소켓 이벤트를 마이크로태스크 큐에서 순차 처리하므로 별도 DB 락(Lock) 없이 안전하게 단일 메모리 연산 가능:
     ```javascript
     fireLife = Math.min(100.0, Math.max(0.0, fireLife + RECOVERY_AMOUNT));
     ```
  2. **클라이언트 낙관적 UI(Optimistic UI)**: 클릭 즉시 장작 던지는 애니메이션을 실행하여 조작 지연감(Latency)을 0으로 체감.

---

### [오류 5] 매크로, 오토클릭, 비정상 패킷 공격 (Abuse & DDoS)
- **원인**: 콘솔창에서 `socket.emit('add_log')`를 무한 루프로 쏘거나 오토클리커를 사용하는 경우.
- **대응 전략**:
  1. **서버 사이드 강제 검증**: 클라이언트 UI 비활성화와 무관하게, 서버 메모리 `Map`에 `socket.id` 및 `client_ip`별 `lastInsertedAt`을 강제 기록. 3분이 지나지 않은 요청은 서버에서 패킷 단계에서 거부 (`cooldown_error`).
  2. **토큰 버킷(Token Bucket) 레이트 리미터**: 동일 IP에서 초당 5회 이상 비정상 패킷 감지 시 일시적 블랙리스트 처리.

---

### [오류 6] 서버 크래시/재배포 시 생존 기록 유실 및 불꽃 단절
- **원인**: 서버 인스턴스 재부팅 시 메모리에 있던 `globalStartTime`과 `fireLife`가 소멸되어 수십 일의 기록이 허무하게 날아감.
- **대응 전략**:
  1. **10초 주기 JSON 영속 스냅샷 (`data/fire_state.json`)**:
     - `fs.promises.writeFile` 비동기 I/O로 디스크에 현재 불꽃 수치, 점화 시각, 총 투입 장작 수 저장.
  2. **오프라인 갭 보정 알고리즘 (Downtime Compensation)**:
     - 서버 재부팅 시 마지막 스냅샷 시각과 현재 시각의 차이(`downtimeDelta`)를 계산하여 다운타임 동안 자연 감쇠된 수치를 정확히 차감 후 복원. 20분 이상 다운되어 계산상 꺼졌다면 정직하게 `EXTINCT` 처리.
  3. **Graceful Shutdown**: `SIGTERM`, `SIGINT` 수신 시 마지막 상태를 동기적으로 디스크에 플러시 후 종료.

---

### ★ [오류 7] 실시간 채팅 XSS(Cross-Site Scripting) 및 악성 스크립트 주입
- **원인**: 악의적 유저가 채팅창에 `<script>fetch('탈취URL')</script>`나 `<img src=x onerror=...>` 등을 전송하여 타 유저의 브라우저에서 실행시키는 공격.
- **대응 전략**:
  1. **서버 & 클라이언트 이중 HTML 이스케이프(Sanitization)**:
     ```javascript
     function sanitizeText(str) {
       return String(str)
         .replace(/&/g, "&amp;")
         .replace(/</g, "&lt;")
         .replace(/>/g, "&gt;")
         .replace(/"/g, "&quot;")
         .replace(/'/g, "&#039;");
     }
     ```
  2. **안전한 DOM 렌더링**: 채팅 렌더링 시 `innerHTML`을 절대 사용하지 않고, 반드시 **`textContent`** 또는 `document.createTextNode`만을 사용하여 렌더링.
  3. **Content Security Policy (CSP) 헤더 적용**: 인라인 스크립트 실행 원천 금지.

---

### ★ [오류 8] 채팅 도배(Spamming), 비속어/욕설 및 화면 가림
- **원인**: 매크로를 이용해 1초에 수십 줄씩 욕설이나 광고를 도배하여 힐링 무드를 파괴.
- **대응 전략**:
  1. **서버 사이드 슬로우 모드 (Rate Limiting)**: 유저 세션별로 마지막 채팅 전송 후 **3초 동안 채팅 차단** (클라이언트 UI 비활성화 + 서버 강제 거부).
  2. **글자 수 및 중복 메시지 차단**:
     - 1회 전송 최대 80자 제한.
     - 직전 메시지와 동일한 내용을 연속 전송 시 차단.
  3. **한국어/영어 비속어 필터링**: 서버에서 정규식 기반 검사 후 마스킹(예: `***`) 처리.

---

### ★ [오류 9] 비정상 접속 종료(Ghost Connection)로 인한 접속자 수 뻥튀기
- **원인**: 브라우저 탭 강제 종료, 모바일 백그라운드 전환 시 TCP 소켓이 정상 `close` 핸드셰이크를 거치지 않아 서버에 유령 세션이 남아 접속자 수가 계속 누적됨.
- **대응 전략**:
  1. **Socket.io 핑퐁 하트비트 (Ping-Pong / 기본 25초, 20초 타임아웃)**: 무응답 세션 자동 감지 및 연결 강제 파기.
  2. **실시간 `io.engine.clientsCount` 기반 브로드캐스트**: 수동 카운트 변수 대신 실제 엔진 활성 커넥션 수를 1초 틱마다 실시간으로 동기화하여 오차 누적을 원천 제거.

---

### ★ [오류 10] 대량 채팅으로 인한 DOM 누수 및 Canvas 프레임 저하
- **원인**: 장시간 켜둘 경우 채팅 메시지 DOM 노드가 수천 개 쌓여 브라우저 메모리가 수 GB까지 팽창하고 캔버스 프레임이 10FPS 이하로 저하됨.
- **대응 전략**:
  1. **최대 메시지 수 큐 제한 (FIFO - First In, First Out)**:
     - 화면에 유지되는 DOM 메시지 개수를 **최대 40개**로 제한. 새 메시지가 들어오면 가장 오래된 첫 번째 자식 노드를 `chatList.removeChild(chatList.firstChild)`로 즉시 메모리 해제.
  2. **메시지 페이드아웃**: 20초가 지난 메시지는 `opacity: 0.3`으로 반투명화되어 시각적 안정감 제공.

---

### ★ [오류 11] 긴 문자열 및 줄바꿈 없는 텍스트로 인한 레이아웃 깨짐
- **원인**: 공백 없는 영문 80자(`aaaaaaaaa...`) 입력 시 채팅 박스 너비를 뚫고 캔버스를 침범.
- **대응 전략**:
  - CSS에 `overflow-wrap: break-word;`, `word-break: break-all;`, `white-space: pre-wrap;` 강제 적용.
  - 최대 너비(`max-width`) 고정 및 커스텀 도트 스크롤바 디자인 적용.

---

### [오류 12] Canvas 파티클 객체 메모리 누수 (Memory Leak)
- **원인**: 수천 개의 불티/연기 파티클 객체를 `new Particle()`로 매 프레임 생성하고 가비지 컬렉터(GC)에 방치할 경우 브라우저 탭 메모리가 폭증함.
- **대응 전략**:
  - **오브젝트 풀링 (Object Pooling)**: 300~500개 고정 파티클 배열을 사전 할당하고 수명이 다한 파티클을 재활용하여 GC 부하를 0으로 수렴.

---

### [오류 13] 초기 유저 부족으로 인한 '15분 컷' 허무한 사망 (Cold Start)
- **원인**: 런칭 초기나 심야 시간대에 동시 접속자가 0명인 순간이 16분만 이어지면 불이 꺼져버림.
- **대응 전략**:
  - 접속자가 2명 이하일 때는 감쇠 속도를 1/3로 늦추어 최대 45분~1시간까지 버틸 수 있도록 유연한 시스템 마진 부여.

---

## 7. 검증 및 테스트 체크리스트 (QA Checklist)

- [ ] **동시성 검증**: 브라우저 창 2개에서 한쪽이 장작을 넣으면 다른 쪽 창에서 0.1초 내로 불꽃이 커지고 알림이 뜨는가?
- [ ] **체류 시간 정밀도**: 백그라운드 탭에서 30분간 다른 작업을 하다 돌아와도 개인 체류 시간이 정확하게 30분 증가해 있는가?
- [ ] **접속자 카운팅 정합성**: 탭을 닫거나 새로고침했을 때 접속자 수가 정확히 동기화되는가?
- [ ] **채팅 XSS 방어**: `<script>alert('xss')</script>`나 `<img src=x onerror=...>` 입력 시 스크립트가 실행되지 않고 안전하게 문자열로 표시되는가?
- [ ] **채팅 도배 방지**: 엔터를 연타해도 3초 쿨다운이 걸려 도배되지 않는가?
- [ ] **장작 쿨다운 검증**: F12 개발자 도구 콘솔에서 `socket.emit('add_log')`를 1초에 100번 호출해도 서버가 차단하고 3분을 엄수하는가?
- [ ] **메모리 안정성**: 2시간 이상 화면을 켜두고 채팅이 오가도 브라우저 탭 메모리가 일정 수준(100MB 이하)으로 안정 유지되는가?
- [ ] **서버 재부팅 복원**: 서버를 강제 종료했다가 다시 켜도 이전의 생존 시간과 화력이 정상 복원되는가?
