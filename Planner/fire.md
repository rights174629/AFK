# 🪵 Keep the Fire Alive (불꽃 지키기 / 멍불)
> **"누군가 장작을 넣지 않으면, 이 불은 꺼집니다."**
> 전 세계 접속자가 단 하나의 실시간 가상 장작불을 함께 돌보며 대화를 나누는 힐링 웹 서비스 개발 계획서 및 기술 예외 대응 전략

---

## 1. 프로젝트 개요 (Overview)

### 1.1 기획 의도 및 철학
- **단 하나의 공유된 불꽃**: 수많은 접속자가 각자의 방이 아닌, 단 하나의 전역(Global) 세션에서 동일한 불꽃을 실시간으로 바라봅니다.
- **장작불 곁의 고요한 대화 (Campfire Community)**: 타닥거리는 장작 소리와 불티 속에서 접속자들이 따뜻한 온기와 일상의 소회를 나눌 수 있는 **미니멀 픽셀 채팅 시스템**을 제공합니다.
- **체류의 기록 (Stay Duration)**: 접속자가 언제 들어와 얼마나 오랫동안 불을 쬐며 쉬어갔는지 개인 세션 체류 시간을 기록하고 시각화합니다.
- **고요한 ASMR & 멍때리기**: 공부, 독서, 수면 전, 업무 중 서브 모니터나 백그라운드 탭에 띄워두는 앰비언스 힐링 공간입니다.

### 1.2 핵심 지표 및 상태
- **불꽃 전체 생존 시간 (Global Lifetime Counter)**: 마지막 점화 순간부터 현재까지 단 1초도 꺼지지 않고 지속된 누적 시간 (DAY, HH:MM:SS).
- **개인 체류 시간 (My Stay Duration)**: 내가 이 장작불 곁에 머문 시간 (예: `🔥 내가 머문 시간: 01:23:45`).
- **실시간 접속자 수 (Live Presence)**: 현재 같은 장작불을 바라보며 사운드와 대화를 나누고 있는 접속자 수 (`● 42명이 함께 불을 쬐는 중`).
- **불꽃 체력 (Fire Life / 0 ~ 100)**: 장작을 넣으면 상승하고, 시간이 지나면 자연 감쇠하는 중앙 상태값.

### 2.1 UI/UX 레이아웃 상세
1. **배경 (Canvas & Atmosphere)**
   - 칠흑 같은 밤하늘과 거친 지면(Pixel Dirt/Grass).
   - Canvas 2D 상에서 불길 강도(`fireLife`)에 따라 지면과 공기를 비추는 **방사형 그라디언트(Radial Ambient Light Glow)**가 부드럽게 펄스(Pulse)하며 확장/수축.
2. **정보 바 (Top Bar)**
   - **좌측 상단**: 개인 체류 시간 (`⏳ 내가 머문 시간: HH:MM:SS`) - 픽셀 폰트, 실시간 카운트업.
   - **상단 중앙**: 불꽃 전체 지속 시간 (`DAY xx · xx:xx:xx`).
   - **우측 상단**: 실시간 동시 접속자 수 (`● N명이 함께 불을 쬐는 중`), 채팅창 접기/펼치기 토글 버튼, 사운드 볼륨/음소거 버튼.
3. **실시간 장작불 채팅창 (Campfire Chat Feed)**
   - 장작불 힐링 감성을 해치지 않도록 **반투명 글래스모피즘(Backdrop-filter blur) + 픽셀 테두리** 디자인.
   - 불필요할 때 접어둘 수 있는 **채팅 숨기기(Minimize) 토글** 지원.
   - 메시지 자동 페이드: 일정 시간(예: 15초) 동안 새 메시지가 없으면 텍스트가 은은하게 반투명화되어 시야 방해 최소화.
   - **익명 닉네임 시스템**: 첫 입장 시 따뜻한 수식어와 동물 이름이 결합된 기본 닉네임 자동 배정 (예: `포근한 사슴`, `조용한 고양이`), 유저가 1회 변경 가능.
4. **하단 상호작용 영역**
   - 픽셀 도트 형태의 장작 버튼. 클릭 시 베지에 곡선(포물선)을 그리며 장작이 불꽃으로 날아감.
   - 3분 쿨다운 동안 도트 게이지 프로그레스 바 작동.

## 3. 핵심 메커니즘 및 시스템 규칙 (Core Mechanics)

### 3.1 불꽃 4단계 수명 시스템 (0 ~ 100)

| 단계 | 수치 (`fireLife`) | 비주얼 연출 | 사운드 특징 | 주변 광원 (Ambient) |
| :--- | :---: | :--- | :--- | :--- |
| **활활 (Blazing)** | 70 ~ 100 | 높이 치솟는 불꽃, 다량의 튀는 불티, 밝은 연기 | 크고 묵직한 포효음, 잦은 타닥거림 | 화면 전체로 넓게 퍼지는 주황/황금빛 광원 |
| **적정 (Steady)** | 30 ~ 69 | 아늑하고 안정적인 크기의 균형 잡힌 불길 | 편안한 기본 ASMR 장작 소리 | 화로 주변 40~50% 반경의 따뜻한 호박색 빛 |
| **잔불 (Dying)** | 1 ~ 29 | 붉게 달아오른 숯, 낮고 깜빡이는 잔불, 짙은 연기 | 불길 소리 급감, 차가운 바람 소리 강조 | 화로 바로 근처만 희미하게 깜빡이는 암적색 빛 |
| **소멸 (Extinguished)**| 0 | 연기만 실바람에 날리는 까맣게 식은 숯더미 | 모든 온기 사운드 정지, 스산한 밤바람 소리만 잔류 | 광원 완전 소멸 (칠흑 같은 밤) |

### 3.2 밸런스 및 수명 감소 공식
- **기본 감쇠율**: 1초당 `0.08 ~ 0.12` 감소 (평균 100에서 0까지 약 15분 소요).
- **장작 1개당 회복량**: `+8` 회복 (최대 100 초과 불가).
- **쿨다운**: 1인당 3분(180초). 즉, 혼자서는 15분 이상 불을 유지할 수 없으며 **최소 2~3인 이상의 주기적인 협동이 필연적으로 요구**됨.

### 3.3 개인 체류 시간 및 접속자 집계 메커니즘
1. **개인 체류 시간 (Stay Duration)**:
   - 유저가 웹페이지에 접속한 타임스탬프(`enterTimestamp = Date.now()`)를 기록.
   - 매초 경과 시간(`Date.now() - enterTimestamp`)을 계산하여 `HH:MM:SS` 포맷으로 갱신.
   - 탭이 백그라운드로 가더라도 `Date.now()` 절대 시간 차이를 이용해 시간 왜곡 없이 정밀 유지.
2. **실시간 접속자 수 (Live Presence)**:
   - WebSocket 연결이 수립될 때마다 서버 접속자 카운트 `+1`, 소켓 연결이 끊어질 때 `-1`.
   - 10초 주기 하트비트(Ping-Pong)로 응답 없는 유령 접속자 자동 정리.
   - 접속자 수 변화 시 모든 클라이언트에 디바운스(Debounce) 적용 후 브로드캐스트.

### 3.4 실시간 채팅 규칙 (Chat Protocol)
- **메시지 길이 제한**: 1회 최대 80자 (장문의 도배 방지, 한두 줄의 힐링 코멘트 권장).
- **채팅 쿨다운**: 1인당 3초에 1회만 전송 가능 (스팸 방지).
- **휘발성 유지**: 서버 DB에 영구 저장하지 않고 최근 30개의 메시지만 메모리 큐에 보관하여 신규 접속자에게 제공.

## 5. ★ 개발 중 발생 가능한 오류 및 전수 대응 계획 (Risk & Error Prevention)

이 프로젝트는 **단일 공유 불꽃 동기화**, **실시간 채팅**, **정밀 시간 집계**, **백그라운드 탭 처리**가 얽힌 복합 시스템입니다. 아래 13대 핵심 오류 및 변수에 대한 구체적 방어책을 수립합니다.

---

### [오류 1] 브라우저 자동 재생(Autoplay Policy) 차단 및 사운드 먹통
- **원인**: Chrome, Safari 등 모든 모던 브라우저는 사용자 제스처(클릭, 터치 등)가 없는 상태에서 `AudioContext` 시작을 강제로 `suspended` 상태로 블록.
- **방어 및 해결 계획**:
  1. 페이지 진입 시 화면 정중앙 하단에 아늑한 픽셀 안내창 배치: *"불꽃의 온기를 들으려면 화면을 한 번 클릭하세요."*
  2. 첫 인터랙션(화면 클릭 또는 탭) 발생 즉시 `audioContext.resume()` 호출 후 안내창 페이드아웃.
  3. 로컬 스토리지에 음소거/볼륨 상태를 저장하여 재방문 시 설정 유지.
  4. 외부 오디오 파일 다운로드 실패 시 Web Audio 노이즈 생성기를 **폴백(Fallback)**으로 가동.

---

### [오류 2] 백그라운드 탭 스로틀링으로 인한 개인 체류 시간 및 불꽃 왜곡
- **원인**: 브라우저 백그라운드 탭 전환 시 `setInterval`이 1분당 1회로 지연되어 단순 `count++` 방식의 타이머는 시간이 멈추거나 느려짐.
- **방어 및 해결 계획**:
  1. **절대 시각 차분 방식 (Date.now Difference)**:
     ```javascript
     // ❌ 잘못된 방식: setInterval(() => staySeconds++, 1000)
     // ⭕ 올바른 방식:
     const elapsedMs = Date.now() - sessionStartTime;
     renderStayTime(elapsedMs);
     ```
  2. **Page Visibility API 연동**:
     ```javascript
     document.addEventListener("visibilitychange", () => {
       if (document.visibilityState === "visible") {
         socket.emit("REQUEST_RESYNC"); // 탭 복귀 즉시 서버 불꽃 상태 최신화
       }
     });
     ```
  3. **선형 보간(LERP)**: 탭 복귀 시 급격한 수치 튐 현상을 부드럽게 보간 렌더링.

---

### [오류 3] 네트워크 불안정 및 소켓 단절 시 상태 고착 (Disconnection)
- **원인**: 모바일 절전 모드, 와이파이 전환 등으로 소켓 세션이 끊길 때 유저가 고립됨.
- **방어 및 해결 계획**:
  1. **지수 백오프(Exponential Backoff)**: 1초, 2초, 4초, 8초 간격으로 백그라운드 자동 재연결.
  2. **비침해적 UI 상태 표시**: 우측 상단 접속자 수를 `● 연결 재시도 중...`으로 은은하게 표시하되 불꽃 캔버스와 사운드는 계속 유지.
  3. **재연결 시 채팅 큐 동기화**: 재접속 완료 즉시 놓친 최근 메시지를 가져와 복원.

---

### [오류 4] 장작 투입 경쟁 상태(Race Condition) 및 동시성(Concurrency) 충돌
- **원인**: 불이 꺼지기 직전 수십 명이 동시에 장작을 넣을 때 발생하는 데이터 덮어쓰기.
- **방어 및 해결 계획**:
  1. **원자적 증감 연산(Atomic Increment)**: 서버 메모리 루프에서 락 없이 원자적으로 계산:
     ```javascript
     currentLife = Math.min(100, Math.max(0, currentLife + RECOVERY_AMOUNT));
     ```
  2. **클라이언트 낙관적 UI(Optimistic UI)**: 클릭 즉시 장작 던지는 애니메이션을 실행하여 조작 지연감(Latency)을 0으로 만듦.

---

### [오류 5] 매크로, 오토클릭, 악의적 트래픽(DDoS/Abuse) 및 게이지 폭주
- **원인**: 콘솔창에서 WebSocket 요청 무한 루프 또는 오토클리커 사용.
- **방어 및 해결 계획**:
  1. **서버 측 강제 검증**: 클라이언트 버튼 비활성화 외에도 서버 메모리에 IP/세션별 `lastInsertedAt`을 강제 기록하여 3분 미만 요청은 서버에서 즉시 `DROP`.
  2. **토큰 버킷(Token Bucket)**: 동일 IP 초당 5회 이상 비정상 패킷 감지 시 일시적 블랙리스트 처리.

---

### [오류 6] 서버 크래시/재배포 시 생존 기록 유실 및 불꽃 단절
- **원인**: 서버 호스팅 인스턴스 재부팅 시 메모리에 있던 `globalStartTime`과 `fireLife`가 소멸.
- **방어 및 해결 계획**:
  1. **영속 스냅샷 (Persistent Snapshotting)**: 매 10초마다 상태를 디스크(JSON/SQLite)에 기록.
  2. **오프라인 갭 보정 알고리즘**:
     - 재부팅 후 마지막 스냅샷 시각과 현재 시각의 차이(`downtimeDelta`)를 계산하여 다운타임 동안 자연 감쇠된 수치를 정확히 차감 후 복원. 20분 이상 다운되어 계산상 꺼졌다면 정직하게 `EXTINCT` 처리.
  3. **Graceful Shutdown**: `SIGTERM` 수신 시 최종 상태 즉시 디스크 플러시.

---

### [오류 7] Canvas 메모리 누수 및 프레임 드랍 (Memory Leak)
- **원인**: 수천 개의 불티/연기 파티클 객체 매 프레임 생성 및 GC 방치로 인한 탭 메모리 팽창.
- **방어 및 해결 계획**:
  1. **오브젝트 풀링 (Object Pooling)**: 500개 고정 파티클 배열을 사전 할당하고 죽은 파티클을 재활용하여 GC 부하를 0으로 수렴.
  2. **저해상도 정수배 스케일링**: Canvas 내부 버퍼는 320x180으로 고정 렌더링하고 CSS `image-rendering: pixelated;`로 화면에 맞게 확대.

---

### [오류 8] 초기 유저 부족으로 인한 '15분 컷' 허무한 사망 (Cold Start)
- **원인**: 심야 시간대 동시 접속자가 0명이 되면 15분 만에 불꽃 사망.
- **방어 및 해결 계획**:
  - 접속자가 2명 이하일 때는 감쇠 속도를 1/3로 늦추어 최대 45분~1시간까지 버틸 수 있도록 유연한 시스템 마진 부여.

---

### ★ [오류 9] 실시간 채팅 XSS(Cross-Site Scripting) 및 악성 스크립트 주입
- **원인**: 악의적 유저가 채팅창에 `<script>fetch('탈취URL')</script>`나 `<img src=x onerror=...>` 등을 전송하여 타 유저의 브라우저에서 실행시키는 공격.
- **증상**: 다른 유저 화면 멈춤, 쿠키/세션 탈취, 화면 왜곡.
- **방어 및 해결 계획**:
  1. **서버 & 클라이언트 이중 HTML 이스케이프(Sanitization)**:
     ```javascript
     function sanitizeText(str) {
       return str
         .replace(/&/g, "&amp;")
         .replace(/</g, "&lt;")
         .replace(/>/g, "&gt;")
         .replace(/"/g, "&quot;")
         .replace(/'/g, "&#039;");
     }
     ```
  2. **안전한 DOM 주입 API 사용**: 채팅 렌더링 시 `innerHTML`을 절대 사용하지 않고, 반드시 **`textContent`** 또는 `document.createTextNode`만을 사용하여 렌더링.
  3. **Content Security Policy (CSP) 헤더 적용**: 인라인 스크립트 실행 원천 금지.

---

### ★ [오류 10] 채팅 도배(Spamming), 비속어/욕설 및 화면 가림
- **원인**: 매크로를 이용해 1초에 수십 줄씩 욕설이나 광고를 도배하여 힐링 무드를 파괴.
- **증상**: 채팅 피드가 빠르게 스크롤되며 화면을 가리고 다른 유저에게 불쾌감 조성.
- **방어 및 해결 계획**:
  1. **서버 사이드 슬로우 모드 (Rate Limiting)**: 유저 세션별로 마지막 채팅 전송 후 **3초 동안 채팅 차단** (클라이언트 UI 비활성화 + 서버 강제 거부).
  2. **글자 수 및 중복 메시지 차단**:
     - 1회 전송 최대 80자 제한.
     - 직전 메시지와 동일한 내용을 연속 전송 시 차단.
  3. **한국어/영어 비속어 필터링 (Profanity Filter)**: 서버에서 메시지 검사 후 마스킹(예: `***`) 처리.
  4. **클라이언트 묵음(Mute/Block) 기능**: 특정 유저의 메시지를 개별적으로 가릴 수 있는 차단 기능 제공.

---

### ★ [오류 11] 비정상 접속 종료(Ghost Connection)로 인한 접속자 수 뻥튀기 및 왜곡
- **원인**: 브라우저 탭을 갑자기 닫거나 강제 종료, 모바일 백그라운드 전환 시 TCP 소켓이 정상 `close` 핸드셰이크를 거치지 않아 서버에 유령 세션(Ghost Session)이 남아 접속자 수가 계속 증가함.
- **증상**: 실제로는 5명인데 화면에는 `● 140명이 함께 불을 쬐는 중`으로 뻥튀기 표기.
- **방어 및 해결 계획**:
  1. **양방향 하트비트 (Ping-Pong / 10초 주기)**:
     - 서버가 클라이언트에 10초마다 핑을 전송하고, 2회 연속(20초) 퐁 응답이 없으면 즉시 소켓을 강제 파기(`terminate()`)하고 접속자 수 `-1`.
  2. **`beforeunload` 이벤트 핸들러**: 브라우저 종료 직전 소켓에 명시적 퇴장 신호 전송.
  3. **접속자 수 스무딩 브로드캐스트**: 1초 단위로 실제 활성 소켓 수(`wss.clients.size`)를 재계산하여 브로드캐스트하므로 오차 누적 방지.

---

### ★ [오류 12] 대량 채팅 렌더링으로 인한 DOM 누수 및 Canvas 프레임 저하
- **원인**: 장시간 켜두는 서비스 특성상 채팅 메시지가 수천 개 쌓이면 DOM 노드가 비대해져 브라우저 스크롤 및 캔버스 렌더링 속도가 급격히 저하됨.
- **증상**: 사이트를 반나절 켜두면 스크롤이 버벅이고 팬이 심하게 돔.
- **방어 및 해결 계획**:
  1. **최대 메시지 수 큐 제한 (FIFO - First In, First Out)**:
     - 화면에 유지되는 DOM 메시지 개수를 **최대 40개**로 제한. 새 메시지가 들어오면 가장 오래된 첫 번째 자식 노드를 `chatList.removeChild(chatList.firstChild)`로 즉시 메모리 해제.
  2. **메시지 페이드아웃**: 20초가 지난 메시지는 `opacity: 0.3`으로 반투명화되어 시각적 안정감 제공.

---

### ★ [오류 13] 긴 문자열 및 줄바꿈 없는 텍스트로 인한 레이아웃 깨짐
- **원인**: 공백 없는 영문 100자(`aaaaaaaaa...`) 입력 시 채팅 박스 너비를 뚫고 캔버스를 침범.
- **방어 및 해결 계획**:
  - CSS에 `overflow-wrap: break-word;`, `word-break: break-all;`, `white-space: pre-wrap;` 강제 적용.
  - 최대 너비(`max-width`) 고정 및 스크롤바 디자인(도트 스크롤바 커스텀).

---

## 7. 검증 및 테스트 체크리스트 (QA Checklist)

- [ ] **체류 시간 정밀도**: 백그라운드 탭에서 30분간 다른 작업을 하다 돌아와도 개인 체류 시간이 정확하게 30분 증가해 있는가?
- [ ] **접속자 카운팅 정합성**: 탭을 닫거나 강제 종료했을 때 10~20초 내에 접속자 수가 정확히 -1 감소하는가?
- [ ] **채팅 XSS 방어**: `<script>alert('xss')</script>`나 `<img src=x onerror=...>` 입력 시 스크립트가 실행되지 않고 안전하게 문자열로 이스케이프되는가?
- [ ] **채팅 도배 방지**: 엔터를 연타해도 3초 쿨다운이 걸려 도배되지 않는가?
- [ ] **채팅 레이아웃 안정성**: 띄어쓰기 없이 `WWWWWW...`를 80자 입력해도 레이아웃이 깨지지 않고 자동 줄바꿈되는가?
- [ ] **오디오 테스트**: 브라우저 첫 진입 시 크래시 없이 인터랙션을 통해 소리가 정상 활성화되는가?
- [ ] **동시성 테스트**: 불꽃이 5% 남았을 때 여러 클라이언트가 동시에 장작을 투입해도 수치가 누락 없이 안정적으로 복원되는가?
- [ ] **메모리 안정성**: 2시간 이상 화면을 띄워두고 수백 개의 채팅이 오가도 브라우저 탭 메모리가 일정 수준(100MB 이하)으로 안정 유지되는가?
